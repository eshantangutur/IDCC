The problem

Debaters practise speaking. Almost nobody practises diagnosing.

A case can sound confident and still fail structurally: an evidence card that never proves its claim, a contention that stops before an impact, a value whose criterion contradicts the argument beneath it. Those failures are hard to see in your own writing, and a coach can only give so many flows.

Structure is invisible

Claims, warrants and impacts blur together in prose. Without a diagram, a dropped link looks identical to a strong one.

Feedback is generic

"Be clearer" and "add evidence" do not tell you which sentence fails, why it fails, or how an opponent answers it.

Formats are not interchangeable

Public Forum weighing, LD framework interaction, Policy DA chains and World Schools team consistency require different standards.

Five specialised modules

One workspace per debate format.

Each format carries its own rubric, focus criteria and analysis tool. Argument Forensics never grades an LD speech with Policy stock-issue standards.

Inside the workspace

Built for the work between rounds.

Interactive argument map

A live graph of claims, evidence, warrants, impacts, assumptions and counterarguments. Select any node to read the source sentence and the reasoning behind the connection — or the missing link.

Weakness detection report

Findings organised by critical, moderate, minor, improvement and strength — each with the passage, the reasoning, why it matters, a concrete revision and a confidence indicator.

Revision workspace

Edit a new version beside the original, see a highlighted diff, re-run the analysis and track which weaknesses disappeared — and which survived the rewrite.

Case archive

Store resolutions, sides, contentions and every analysed speech version in one place. Search, filter, revisit and re-run any report.

Defined rubrics, no invented scores

Five dimensions per format, each with a written definition and a 1–5 scale. No opaque "argument score" is ever generated.

Private by construction

Server-side sessions, hashed passwords and every query scoped to your account. Your speeches are never shared with another user.

The analysis process

Paste a speech. Receive a structure, not a chat reply.

The backend sends your speech to the configured language model with the rubric and vocabulary of your chosen format, then validates the response against a strict schema before anything reaches the screen.

Select the standard

Choose one of five formats, your side and the speech type. Each selection changes the rubric and the format-specific tool.

Extract the structure

The model returns claims, evidence, warrants, impacts, assumptions, counterarguments, relationships and a node graph.

Validate and persist

The server rejects malformed output, normalises every field, and stores findings, nodes and edges against your account.

Revise and compare

Rewrite the speech, re-analyse it, and see which findings resolved — with the exact new text as evidence.

Analyses are judgments, not verdicts. Argument Forensics separates factual inaccuracy, missing evidence, logical weakness and strategic advice, and attaches a confidence indicator to every finding. A model can be wrong; the cited passage is always shown so you can check it.
Security & honesty

A workspace you can put real work into.

Passwords are hashed with bcrypt, sessions live in SQLite with HttpOnly SameSite cookies, every state-changing request carries a session-bound CSRF token, and API access is rate limited. AI keys stay in the server environment and are never sent to the browser.

If no AI credentials are configured, the application runs in a clearly labelled demo mode using local structural heuristics. It will never present heuristic output as a model analysis.
